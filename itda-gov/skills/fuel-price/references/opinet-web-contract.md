# 오피넷 평균판매가격 화면 — 관측 계약과 표본

`parse` 가 기대는 오피넷 화면의 성질을 **관측 표본 수와 함께** 적는다. 여기 적힌 것은 계약이 아니라
"지금까지 이렇게 보였다" 이다(규칙 `collection-completeness` ⑩). 어긋나는 응답이 나오면 이 문서와
해당 코드부터 의심하고, 새 실측으로 고친 뒤 표본을 늘린다.

## 1. 확인된 것

| 성질 | 표본 | 코드 |
|---|---|---|
| 조회 POST 는 쿠키 없이, 범용 UA(`Mozilla/5.0`)로 성립한다 | itda-hyve 실측 8회 + 리뷰 curl 실측(2026-09-30, 전국·시도 × 월·주·일) | SKILL 호출 JSON 에 UA·Cookie 없음 |
| 응답 화면은 조회 조건(TERM·시작/종료 셀렉트·제품·지역 체크)을 되비친다 | 실측 응답 전부 | `opinet_web.parse_form_echo` |
| 응답의 `h_max*` 는 요청에 실은 값이 아니라 **서버의 현재 값**이다 | 2회 — 전국·시도 각 1(09-01 화면 값으로 보낸 POST 가 `h_maxDD=20260929`) | `fuel_price._check_range_vs_args` |
| 자료 없는 기간의 행은 표에서 빠진다(앞쪽 결손) | 전남광주 월·주·일(2026-07 통합), 세종 주간(2012년11월3주부터) | `fuel_price._check_period_rows` |
| 긴 범위의 앞쪽을 서버가 자르지 않는다 | 전국 일간 400일 1회 | 앞쪽 결손 = 자료 시작으로 읽는 근거 |
| 주간 라벨 `YYYY년MM월N주` 는 **그 달 N번째 수요일이 든 주**다 | 응답 8종 — 2012-11~12 세종 6주, 2025-08~2026-08 전국 56주, 2026-07~09 전국·인천·전남광주, 09-02·09-30 두 시점. 리뷰 3차 라이브(2026-09-30) 전국 918주·세종 432주·제주 439주 전수 대조, 어긋남 0 | `opinet_web.expected_weeks` |
| 전국 주간 자료는 **2008년 1월 1주**부터 있다(그 앞 주간 규칙은 확인할 대상이 없다) | 리뷰 3차 라이브 1회 | 앞쪽 결손 = 자료 시작으로 읽는 근거 |
| 조회에 쓰이지 않는 셀렉트(분기, 월·주간의 일)는 서버가 쓰지 않는다 — 브라우저는 그날 화면 기본값을, 스킬은 유효한 옵션 값을 보낸다 | 2026-09-02·09-30 브라우저 직렬화 ↔ 빌더 응답 표 값 일치 | `tests/test_payload_golden.py` |

## 2. 표본이 얇은 것 — 주간 표의 최신 주

- 관측: 2026-09-02(수, `h_maxDD=20260901`)에는 표가 `08월4주`(수 08-26)까지, 2026-09-30(수, `h_maxDD=20260929`)에는
  `09월4주`(수 09-23)까지 있었다. 두 날 모두 **수요일이 `h_maxDD` − 6일인 주까지** 있었다.
- 코드는 여기에 하루 여유를 더해 "수요일이 `h_maxDD` − 7일 이전인 주는 반드시 있어야 하고, 그 뒤 주는 없어도 된다"
  (`fuel_price.WEEK_TAIL_SLACK_DAYS = 7`)로 둔다. 최신 한 주가 빠진 표는 실패로 잡지 않는다 — 그 주가 아직 안 올라온
  것인지 잘린 것인지 표본으로는 가를 수 없어서다.
- **사이트가 밝힌 것(실측 아님)** — 전국 화면과 응답 픽스처 모두에 "주간평균 가격은 해당 주 일요일~목요일의 평균 가격임(금요일에 주간
  통계 발표)" 가 있다(`tests/fixtures/view-nat-20260930.html`). 이 문구대로면 주간 행은 수요일 + 2일(금) 무렵 올라온다 — 그러면
  매주 목요일(발표 전) 정상 조회에 "최신 주(…)가 응답에 없습니다" 가 붙는다(예: 2026-10-01(목) → `09월5주`). 문구가 정직해 결함은
  아니고, 실측 뒤 7일 여유를 줄일 근거가 된다.
- `h_maxWW`(예: `2026095`) 의 의미는 확정하지 못했다("진행 중인 주" 로도 "날짜 ÷ 7 올림" 으로도 두 표본이 설명된다).
  그래서 **행 대조**는 `h_maxWW` 에 기대지 않고 `h_maxDD` 와 수요일 규칙만 쓴다. 다만 `--end` 없는 주간 조회의 **끝 달**은
  여전히 `h_maxWW` 의 연월에서 온다(`opinet_web.period_range`). 달이 어긋나도 대조는 성립하지만, `h_maxWW` 의 달이 `h_maxDD` 를
  앞지르면 앞 달의 수요일 일부가 기대 목록에서 떨어져 **표가 요청 수보다 짧아질 수 있다** — 그때는 `warnings` 에 "요청한 N주 중 M주만
  보입니다" 가 붙고, 필수 주가 하나도 남지 않을 만큼 어긋나면 `site` 다(W7m d1 — 리뷰 시뮬레이션상 해석 B(당일 기준)에서 달초
  `h_maxDD` 가 이틀 이상 묵을 때만 생긴다).
- 여유 안의 최신 주가 없는 표는 정상으로 보고 `warnings` 에 "최신 주(…)가 응답에 없습니다" 한 줄을 싣는다(W7c c1·c2).
  행 수 게이트는 두지 않는다 — 범위 산식(앞 달마다 4주 이상)이 기대 목록을 늘 요청 수 이상으로 잡으므로, 이어짐·뒤쪽 필수
  검사를 지난 표가 모자랄 수 있는 것은 그 최신 주 하나뿐이다. 옛 게이트는 기대 목록이 요청 수와 딱 맞는 `--periods` 에서만
  이 정상 상태를 `period` 로 막았다(09-02 픽스처 기준 `--periods 3·5·8` 은 ok, `4` 만 실패 — 거짓 실패).

## 3. Cowork 실측 대기 (itda-hyve 0.10.4 공개 뒤)

| 항목 | 왜 | 볼 것 |
|---|---|---|
| **목요일·금요일(발표 전후 시각) 기본 주간 조회** — 가장 가까운 표본 **2026-10-01(목)·10-02(금)**, 그리고 **2026-10-08(목)** | 위 2절의 실측 표본이 수요일 둘뿐이고, 사이트 문구(금요일 발표)가 맞는지 재지 않았다. 1일이 목요일인 10월은 첫 주(10-04~10-10) 경계가 가장 나쁘다 | `plan`→`parse --term week` 가 `period` 없이 통과하는가, 목요일에 "최신 주" 경고가 붙고 금요일 발표 뒤 사라지는가, 표의 마지막 주 수요일과 `h_maxDD` 의 간격. 여유(7일)를 줄일지, 요청한 주 수를 꼭 채울지(채워야 하면 범위를 `ceil((periods+1)/4)` 달로)는 이 결과로 정한다 |
| 2026-11-01(일)·11-02(월) `--term week --periods 4` | 10월은 수요일이 넷(10-31 토)이라 기대 목록이 요청 수와 딱 맞는다. 10월4주(수 10-28)가 아직 없으면 **3주만 보이고** 경고 한 줄로 통과한다(옛 개수 게이트라면 `period`). 다만 금요일 발표가 맞으면 10월4주는 10-30(금)에 올라와 있어 **이 날은 아무것도 가르지 못한다** — 위 목·금 표본이 우선이다 | 표의 마지막 주, `warnings` 의 "최신 주(2026년10월4주)" 문구, `h_maxDD` |
| 오피넷 새벽 갱신 시각 | 갱신 전에 받은 화면·결과는 그날 재사용된다(`warnings` 로만 알린다) | 00~06시 사이 `h_maxDD` 가 바뀌는 시각 |
| Open API 경로(`avgRecentPrice`·`areaAvgRecentPrice`) | 키를 쿼리로 보내는 경로라 0.10.3 `final_url` 결함 때문에 한 번도 부르지 않았다 | 응답 필드(`DATE`·`PRODCD`·`AREA_CD`)·날짜 연속성·최신 날짜가 받은 날 기준 며칠 전인지(`API_FRESH_DAYS=3` 의 타당성)·`secret_missing` |
| itda-hyve 가 오류 상태(403·5xx) 본문을 저장하는 모양 | SKILL 의 "status 가 200 이 아니면 넘기지 않는다" 규칙의 전제 | 저장 파일과 응답 요약의 `status` |
