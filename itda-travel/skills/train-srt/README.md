# train-srt — 폐기 기록 (#1624)

> **상태: deprecated (2026-09-01).** 검색·예약 기능 없음. 통합 안내 스텁.
> 사용법은 [GUIDE.md](GUIDE.md), 실행 계약은 [SKILL.md](SKILL.md) 참조.
> 열차 검색·예약은 자매 스킬 **train-ktx** 가 담당합니다.

## 왜 폐기했는가

SRT는 2026-09-01부로 폐지되고 KTX로 통합됐습니다. **9월 1일 이후 운행 열차는
코레일+ 앱·코레일 홈페이지에서만 예매 가능**하며, SR 앱(etk.srail.kr) 예매는
8월 31일 운행분까지였습니다.

## 어떻게 발견했는가 — 조용한 전량 필터링

통합 직후 `train-srt search` 가 **0건**을 반환했습니다. 예외도 나지 않고
`--include-no-seats` 로도 0건이라 "열차 없음"으로 위장되는 형태였습니다.

SR 서버 원 응답을 직접 찍어 원인을 갈랐습니다:

- 서버는 **정상 응답**(HTTP 200 · `IRG000000 정상처리` · 수서 `0551`→부산 `0020` ·
  SRT 303/305/307)을 주고 있었습니다.
- 그런데 열차종별 코드 `stlbTrnClsfCd` 가 **`00`/`07`/`0A`** 로 바뀌었습니다
  (분포: `0A`×7 · `07`×2 · `00`×1).
- `SRTrain` 2.6.7(최신)의 매핑은 `17 = SRT` 뿐이라 `srt.py` 의
  `train_name == "SRT"` 필터가 **전량 제거** → 0건.

증명: `TRAIN_NAME` 에 `00/07/0A → SRT` 를 임시 주입하자 같은 어댑터가 **25건**
반환. 즉 `00`/`07`/`0A` 는 버그가 아니라 **KTX 코드 체계로의 정상 전환**이고,
`SRTrain` 의 매핑이 낡은 것입니다.

## 왜 어댑터를 고치지 않았는가

고치면 검색은 되살아나지만 **공식적으로 예매가 중단된 경로**로 사용자를 보내게
됩니다. 예약 단계에서 조용히 실패하면 사용자는 좌석을 잡은 줄 압니다
(`no-silent-fallback` 의 최악형 — 실패가 아니라 성공 위조).

그리고 **그 열차를 코레일이 이미 팝니다.** 2026-09-02 수서→부산 라이브 대조:

| | SR API | 코레일 API |
|---|---|---|
| 열차번호 | 303 · 305 · 307 · 309 | **303 · 305 · 307 · 309** |
| 종별코드 | `07` · `0A` · `00` | **`07` · `0A` · `00`** |
| 06:00 편 요금 | 52,400원 | **52,400원** |
| 표기 | (필터에 걸려 0건) | "KTX-산천" |

같은 재고입니다. 코레일이 SRT 전용역 전 구간을 판매함도 확인했습니다(각 10건):
수서→부산/동대구/광주송정 · 평택지제→부산 · 동탄→부산 · 부산→수서.

## 열차명·차량도 소멸했다

**"SRT" 라는 열차명 자체가 없어졌습니다.** 차량은 한국철도공사로 이관됐습니다 —
임대분 120000호대 **22편성**과 SR 발주분 130000호대 **10편성**이 반환되어 전 편성이
**KTX-산천으로 편입**됐습니다. 우리가 관측한 종별코드 `07`·`0A`(KTX-산천)와
`00`(KTX)가 그 결과입니다.

따라서 이 스킬이 되살아나더라도 `train_name == "SRT"` 로 거를 대상이 **애초에 존재하지
않습니다.** SRTrain 의 필터를 고치는 문제가 아니라 대상이 소멸한 것입니다.
