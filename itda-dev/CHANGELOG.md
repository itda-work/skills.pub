  `qiě` 가 됐다. 낱말 안에서 모음으로 시작하는 음절 앞에 ’ 를 다시 넣는다.

## [0.12.0] — 2026-08-25

**원천 데이터 검증 층 신설.** 그동안의 검사는 전부 "한글이 병음·가나와 맞는가" 만 봤다 —
**병음·로마자 자체가 맞는지는 아무도 보지 않았다.** 병음이 틀리면 생성기는 그 틀린 병음을
충실하게 한글로 옮기고 세 층 전부 통과한다. 원어민 감수가 불가능한 상황에서 이 층이
"AI 검수" 의 첫 단계다 — LLM 판정이 아니라 **사전 대조**라 증거로서 가장 강하다.

### Added

- `scripts/verify-pinyin.mjs` — 한자 → pypinyin 사전 병음 → 우리 성조 변화 → 데이터 병음
  대조. 결과: **읽기 불일치 0건**(다음자 오선택 없음), 성조 불일치 0건(교정 후),
  경성 처리 14건(오류 아님), 사전 한계 1건(`哇` — 문두 감탄사 wā 를 pypinyin 은 문말

## [0.11.0] — 2026-08-25

**SPEC.md 를 v1.3 으로 고쳐 J1 의 빈틈을 막았다.** 앞 버전에서 "데이터를 고치고 SPEC 은
그대로 둔다" 고 했는데, 그 판단의 전제였던 "저자의 표기 관행" 이 **존재하지 않았다** —
이 앱의 중국어·일본어 콘텐츠에는 원저자가 없고 전량 이전 세대 생성물이다(SPEC 이 참조하는
종이 교재는 영어뿐). 즉 `て`→테 는 사람의 음성 직관이 아니라 **규칙이 덜 적용된 흔적**이다.

측정이 그것을 뒷받침한다. 원본 표기는 두 규범 어느 쪽과도 일치하지 않는 **혼입**이었다 —
`と`·`た` 는 SPEC 쪽(또·따), `て` 와 `ました` 의 `た` 는 외래어 표기법 쪽(테·타). 빈틈은
J1 이 た행 예시를 하나도 주지 않은 것이었으므로, **데이터가 아니라 규칙을 조인다.**

- 외래어 표기법과 반대인 이유를 각주로 명시하되, **J1 은 검증된 음성학이 아니라 설계

  떼지 않는다. 띄어쓰기는 호흡의 표기일 뿐 소리를 바꾸지 않는다(원리 5·6).
  (`から` 를 분리 목록에 넣은 근거가 데이터 1건이었다 — 함정 2를 내가 어긴 자리다.)
- **띄어쓰기 유무로 결과가 갈리던 것** — `ごはんをたべよう` 가 고항오**따**베요ー 였다.
  `を` 는 언제나 조사이므로 **낱말 안에 있어도 끊는다.** 이제 `ごはんを たべよう` 와 같다.
- **`はを`(歯を, 이를)의 は 를 조사로 읽던 것** — 하 가 와 로 뒤집혔다. 조사인지 여부를
  위치로 짐작하지 않고 값으로 들고 다닌다.

### Added

- `check-data.mjs`(웹사이트 저장소)에 **J1 검사** — ㅋ·ㄲ 는 か행에서만, ㅌ·ㄸ 는 た·て·と
