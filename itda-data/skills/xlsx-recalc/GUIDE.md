---
title: "xlsx-recalc 사용 가이드"
---

파이썬(openpyxl)이나 다른 도구로 만든 엑셀 파일은 **수식은 들어 있는데 계산된 값이 비어 있는** 경우가 많습니다.
Excel 로 열면 그 자리에서 다시 계산해 멀쩡해 보이지만, 미리보기·pandas·다른 분석 스킬은 빈칸이나 0 을 봅니다.
이 스킬은 LibreOffice 로 값을 채워 **새 파일**로 돌려줍니다. **Claude에게 말로 부탁하면 됩니다.**

---

## 이럴 때 쓰세요

- Claude 가 openpyxl 로 만들어 준 엑셀을 **미리보기로 열었더니 합계 칸이 비어 있다**
- pandas 로 읽으면 수식 칸이 전부 `NaN` 이다
- 만든 엑셀을 data-audit·data-verify 로 점검하기 **전에** 값을 채워 두고 싶다
- 거래처에 보낼 파일인데, Excel 이 없는 사람이 열어도 숫자가 보이게 하고 싶다

---

## 빠른 시작

```
/xlsx-recalc 매출집계.xlsx 수식 값 채워줘
/xlsx-recalc 방금 만든 보고서 엑셀 재계산해줘
/xlsx-recalc 첨부한 원장.xlsx 결과는 원장-값채움.xlsx 로 저장해줘
```

슬래시 없이 "이 엑셀을 pandas 로 열면 합계가 빈칸이야. 값이 보이게 해줘" 처럼 말해도 됩니다.

파일을 첨부하거나, 대화에서 방금 만든 파일 이름을 말하면 됩니다. Claude 가 알려 주는 것은 네 가지입니다.

1. 결과 파일 위치 — 원본 옆에 `매출집계-recalc.xlsx` 처럼 새로 만듭니다. 다른 이름이나 위치를 원하면 함께 말하세요.
2. 계산한 수식 개수와 사용한 LibreOffice 버전
3. 계산 결과가 에러인 칸 — 예: `매출!D3 #DIV/0!`
4. (있으면) 저장하면서 수식 표기가 바뀐 칸

원본 파일은 건드리지 않습니다.

---

## 얼마나 걸리나

Cowork 에서 직접 재 본 시간입니다(LibreOffice 26.2).

| 파일 | 걸린 시간 |
|---|---|
| 수식 몇 개짜리 작은 표 | 약 0.3초 |
| 2만 행 원장, 수식 약 2만 개 | 약 0.8초 |

기본으로 3분까지 기다립니다. 그보다 오래 걸리면 멈추고 알려 드리며, 스스로 다시 시도하지 않습니다.
더 기다려도 되면 "시간을 늘려서 한 번 더" 라고 말하세요.

---

## 준비물

- **LibreOffice 24.8 이상.** Cowork 에는 이미 들어 있습니다. 내 컴퓨터에서 쓴다면 [libreoffice.org](https://www.libreoffice.org) 에서 설치하세요.
- 그보다 오래된 LibreOffice(예: 7.x)는 거부합니다. 최신 함수(XLOOKUP 등)를 몰라 **에러 없이 틀린 값**을 내기 때문입니다.
- 그 밖에 따로 설치할 파이썬 패키지는 없습니다.

---

## 결과를 받으면

- **에러 칸**: `#DIV/0!`(0으로 나눔), `#N/A`(찾는 값 없음) 같은 칸은 원래 수식이 그렇게 계산된 결과입니다.
  고칠지는 직접 판단하세요. 수식 자체가 틀렸는지 점검하려면 data-audit 을 이어서 쓰면 됩니다.
- **수식 표기가 바뀐 칸**: LibreOffice 는 저장하면서 수식을 조금 다르게 적기도 합니다(`TRUE` → `TRUE()` 등). 대부분 의미는 같습니다.
  다만 **다음에 다시 계산하면 값이 달라질 수 있는 변화**는 칸과 바뀌기 전후 수식을 따로 보여 드립니다.
  예: `ROUND(0.49999999999999994,0)` 이 `ROUND(0.5,0)` 으로 바뀌면 지금은 0 이지만 다음 계산에서는 1 이 됩니다.
- **수식은 그대로 남습니다.** 값만 채워질 뿐, 결과 파일을 Excel 에서 열면 수식이 그대로 보입니다.

---

## 계산하지 않고 멈추는 경우

이 스킬은 **틀린 값이 든 파일을 정상처럼 넘기지 않는 것**을 가장 중요하게 여깁니다. 아래 경우에는 결과 파일을 만들지 않고 이유를 알려 드립니다.
Claude 가 다른 방법으로 값을 억지로 채우지도 않습니다.

| 상황 | 이유 | 이렇게 하세요 |
|---|---|---|
| 다른 엑셀 파일을 참조하는데, 그 값이 파일에 저장돼 있지 않다 | 참조 대상을 읽을 수 없어 0 이나 오류가 들어간 결과가 나옵니다 | 원본을 Excel 에서 열어 **링크 업데이트 후 저장**하고 다시 부탁하세요 |
| 수식에 다른 파일 이름만 적혀 있다(예: openpyxl 로 `[거래처.xlsx]Sheet1!A1` 을 직접 넣음) | 계산에 쓸 값이 파일 어디에도 없습니다 | 위와 같습니다. 참조 대상 파일과 함께 Excel 에서 열어 저장하세요 |
| LibreOffice 가 24.8 보다 오래됐다 | 최신 함수를 몰라 틀린 값을 냅니다 | LibreOffice 를 업데이트하세요 |
| 실행 환경이 LibreOffice 에 필요한 통신 방식(소켓)을 막았다 | LibreOffice 가 시작하지 못합니다 | 다른 환경(Cowork·내 컴퓨터)에서 실행하세요 |
| 데이터 테이블(가상 분석 표)이 들어 있다 | LibreOffice 가 Excel 에 없는 수식으로 바꿔 저장해 Excel 에서 깨집니다 | 이 파일은 Excel 에서 직접 계산하세요 |
| "Strict Open XML" 형식으로 저장된 파일이다 | 이 형식은 검증할 수 없습니다 | Excel 에서 일반 "Excel 통합 문서(*.xlsx)" 로 다시 저장하세요 |
| 계산은 끝났는데 결과 점검에서 걸렸다(수식 소실·외부 링크 변경 등) | LibreOffice 가 저장하며 원본과 다른 파일을 만들었습니다 | Claude 가 보여 주는 메시지를 확인하세요. 대부분 Excel 에서 직접 계산하는 편이 안전합니다 |
| 너무 오래 걸린다(기본 3분) | 무한정 기다리지 않습니다 | 더 기다려도 되면 말씀해 주세요. 시간을 늘려 한 번 더 시도합니다 |

## 자주 묻는 질문

**원본 파일에 바로 덮어써 줄 수 없나요?**
스킬은 원본을 덮어쓰지 않습니다. 결과 파일을 열어 확인한 뒤 원본을 바꾸고 싶다면 직접 교체하거나, Claude 에게 결과 확인 후 교체를 따로 부탁하세요.

**openpyxl 로 값을 직접 넣으면 되지 않나요?**
수식 결과를 사람이 계산해 넣으면 수식과 값이 따로 놀게 됩니다. 이 스킬은 오피스 프로그램이 수식을 실제로 계산한 값만 채웁니다.

**다른 파이썬 계산기가 더 빠르지 않나요?**
파이썬·Go 로 만든 수식 계산기 7종을 LibreOffice 결과와 한 칸씩 대조했더니, **모두 에러 없이 틀린 값을 내는 경우가 있었습니다.**
SUM·SUMIFS·VLOOKUP·ROUND·TEXT 같은 흔한 함수에서도 그랬습니다.

| 수식 | LibreOffice | 빠른 계산기 중 하나 |
|---|---|---|
| "취소"가 들어간 행 세기(SUMPRODUCT 와 SEARCH 조합) | 2 | 1 |
| 0.3 을 소수 첫째 자리에서 내림(ROUNDDOWN) | 0.3 | 0.2 |
| 연말을 넘기는 두 달 뒤 날짜(EDATE) | 다음 해 1월 | 같은 해 1월 |

그래서 느리더라도 오피스 프로그램이 직접 계산하는 방법 하나만 씁니다.

**한글 파일 이름이나 공백이 있는 폴더도 되나요?**
됩니다. `고객 자료 폴더/원장 2026.xlsx` 같은 경로로 확인했습니다.

**1904 날짜 체계나 "표시 형식대로 계산" 설정은요?**
파일에 저장된 설정 그대로 계산합니다.

---

## 이런 때는 다른 스킬

| 하고 싶은 것 | 스킬 |
|---|---|
| 수식 오류·하드코드·범위 누락 찾기 | data-audit |
| 합계·원장 대조로 값 검산 | data-verify |
| 데이터로 디자인된 엑셀 새로 만들기 | xlsx-design |

엑셀을 새로 만들었다면 **만들기 → 재계산(이 스킬) → 점검** 순서가 좋습니다. 점검 스킬은 파일에 저장된 값을 읽기 때문입니다.

---

## 알아 두면 좋은 것

- **원본은 그대로 둡니다.** 결과는 항상 새 파일입니다.
- 결과 값은 **LibreOffice 가 계산한 값**입니다. LibreOffice 와 Excel 이 다르게 계산하는 드문 경우(참/거짓 값을 더하기, 따옴표 속 숫자 더하기 등)에는 Excel 에서 다시 계산하면 달라질 수 있습니다.
- 다른 파일을 참조하는 수식은 **파일에 저장돼 있던 참조 값**으로 계산합니다. 참조 대상 파일을 새로 읽지 않으므로, 저장된 값이 오래됐으면 결과도 오래된 값입니다.
- 수식이 하나도 없는 파일은 계산 없이 그대로 복사합니다.
