---
title: "morning-brief (아침 브리핑) 사용 가이드"
---

오늘 일정과 아직 답하지 않은 메일을 모아 **아침에 한눈에 보는 한 장**으로 그려 줍니다.
한 장에 담기는 것은 셋입니다.

- **오늘 일정 전체** — 시간순으로, 시간·제목·장소·참석 인원
- **일정별 관련 메일** — 그 자리의 참석자와 주고받은 메일이 각 일정 곁에 붙습니다
- **일정과 무관한 미회신 메일** — 사람이 보낸 메일 중 아직 답하지 않은 것, 제목·보낸 사람·내용 요약

뉴스레터·자동 알림 같은 메일은 따로 모아 제목만 보여 주고, 그 아래 날씨(기본)·환율 절이 붙습니다.
모양은 기본 **타임라인**이고, 보고서·표·인쇄용 모양으로도 받을 수 있습니다(아래 「모양 고르기」).

**`/morning-brief` 뒤에 지침을 붙여 입력하면 됩니다.** 결과는 HTML 파일 한 장으로 저장되고, 다 만들면
Claude 가 **미리보기**를 띄웁니다(아래 「활용법」). 계정을 아직 연결하지 않았어도 **샘플 브리핑**으로
형식을 먼저 볼 수 있습니다.

Claude Cowork 와 Claude Code 에서 씁니다. 메일·일정은 **itda-hyve**(내 PC 에서 도는 연결 프로그램)를 거쳐 읽습니다.

---

## 빠른 시작

```
/morning-brief 아침 브리핑 만들어줘
```

```
/morning-brief 오늘 브리핑 보여줘
```

일정과 메일은 itda-hyve 에 등록한 계정에서 읽어 옵니다 — `itda-work:calendar`·`itda-work:email` 이
쓰는 계정과 같습니다. 둘 중 하나만 연결돼 있어도 그 부분만으로 페이지를 만듭니다.

---

## 모양 고르기 — 네 가지 스타일

같은 일정·메일을 **네 가지 모양**으로 그릴 수 있습니다. 담기는 내용은 넷 모두 같고 배치만 다릅니다.
아무 말도 하지 않으면 타임라인이고, 요청에 한마디를 붙이면 다른 모양이 됩니다.

| 이렇게 말하면 | 모양 | 어울리는 때 |
|---|---|---|
| (아무 말 없음) · "타임라인으로" | **타임라인** — 하루를 세로 시간축으로. 일정이 길수록 블록이 길고, 1시간 이상 빈 시간이 보이며, 관련 메일이 일정 옆에 붙습니다(휴대폰에서는 아래) | 미팅·강의가 많은 날 |
| "보고서 형식으로" · "메모처럼" | **보고서** — 날짜·계정·날씨를 적은 머리, "오늘은 일정 N건, 답을 기다리는 메일 M통이에요." 한 줄, 그 아래 차분한 목록 | 위에서 아래로 한 번 정독할 때 |
| "표로" · "대시보드처럼" | **표** — 맨 위에 수(일정·관련 메일·미회신·대량 발송), 일정 표 아래에 관련 메일 하위 행 | 메일이 많은 날, 숫자부터 볼 때 |
| "인쇄용으로" · "PDF 로 저장할래" | **인쇄용** — A4 한 장 두 단(왼쪽 일정·오른쪽 메일), 검은 머리띠 | 출력해서 책상에 둘 때 |

그 밖의 이름(카드형 등)을 말하면 가까운 것을 고르지 않고 이 네 가지를 알려 줍니다.

어느 모양이든 화면 설정이 다크 모드면 어두운 색으로 열리고(인쇄는 늘 밝은 색), 휴대폰 너비에서도
옆으로 밀리지 않습니다.

## 사전 준비 — itda-hyve 와 계정

이 스킬은 자체 계정을 따로 두지 않습니다. 메일·일정은 **itda-hyve** 가 읽어 옵니다. itda-hyve 는
내 PC 에서 도는 작은 연결 프로그램이고, 계정 비밀번호는 그 안의 금고에만 있습니다. Claude 는
비밀번호를 보지 못하고, 이 스킬도 비밀번호를 묻거나 파일에서 읽지 않습니다.

### 1. itda-hyve 준비 — 0.9.6 이상

itda-hyve 를 설치하고 Claude Desktop 에 연결합니다(받는 곳 [itda.work/hyve](https://itda.work/hyve/)). 필요한 판은 이렇습니다.

| 하려는 것 | 필요한 itda-hyve |
|---|---|
| 브리핑 만들기 | **0.9.6 이상** |
| 다 만든 브리핑을 내 PC 의 브라우저로 열기(선택) | **0.10.1 이상** |

판이 모자라면 스킬이 **브리핑을 만들기 전에** 업데이트를 안내하고 멈춥니다(아래 「itda-hyve 업데이트」).
itda-hyve 가 없거나 연결되지 않았으면 설치 안내를 하고 멈춥니다.

macOS 에서 처음 쓰면 "itda-hyve 가 위치를 사용하려고 합니다" 창이 뜰 수 있습니다. 허용하면 날씨가 구 단위까지 맞습니다.

**Cowork 에서는 작업 폴더를 연결해 두세요.** itda-hyve 가 받아 온 메일·일정을 그 폴더에 저장하고, 브리핑 파일도
그 폴더의 `outputs/` 에 남습니다. 연결한 폴더가 없으면 폴더를 연결해 달라고 요청하고 멈춥니다.

### 2. 계정 등록

itda-hyve 화면의 계정 탭에서 메일 계정(네이버·Gmail·다음·아이클라우드·회사 메일)을 등록합니다.
일정은 네이버·아이클라우드 계정, 또는 캘린더 주소를 넣은 직접 입력 계정에서 읽습니다. 절차는
`itda-work:email`·`itda-work:calendar` 의 가이드와 같습니다. 따로 설치할 것은 없습니다.

### 3. 연결이 없어도 동작합니다

등록된 계정이 없는 역할은 **조용히 비워 두고** 진행합니다. 스킬이 대신 설정해 주지 않고,
"연결하세요" 같은 안내 카드로 페이지를 채우지도 않습니다. 두 역할 모두 없으면 두 문장짜리
페이지가 나오고, 그 아래 "샘플 브리핑을 요청하면 형식을 미리 볼 수 있어요" 한 줄이 붙습니다.

### 어떻게 모으나요

Claude 가 itda-hyve 에게 **두세 번에 나눠 한꺼번에** 묻습니다 — 계정 목록과 현재 위치, 오늘 일정(참석자 포함)·
최근 이틀 받은 메일·최근 한 달 보낸 메일·날씨 예보, 그리고 미회신 메일의 본문 앞부분. itda-hyve 가 이것들을
내 PC 에서 동시에 받아 작업 폴더에 저장합니다. 무엇을 받을지, 답장했는지, 어떤 메일이 어느 일정과 이어지는지는
**스킬의 스크립트가 정합니다.** Claude 가 쓰는 것은 미회신 메일의 **요약 문장**뿐입니다.

## 자주 쓰는 요청

| 하고 싶은 것 | 이 지침을 입력하세요 |
|---|---|
| 기본 브리핑 | `/morning-brief 아침 브리핑 만들어줘` |
| 오늘치 다시 보기 | `/morning-brief 오늘 브리핑 보여줘` |
| 보고서 모양으로 | `/morning-brief 아침 브리핑 보고서 형식으로 만들어줘` |
| 표로 한눈에 | `/morning-brief 아침 브리핑 표로 보여줘` |
| 출력·PDF 용 | `/morning-brief 아침 브리핑 인쇄용으로 만들어줘` |
| 환율까지 함께 | `/morning-brief 아침 브리핑 만들어줘. Sections: 날씨,환율` |
| 환율만 | `/morning-brief 아침 브리핑 만들어줘. Sections: 환율` |
| 날씨 절 빼기 | `/morning-brief 아침 브리핑 만들어줘. Sections: none` |
| 실행 버튼까지 달기 | `/morning-brief 아침 브리핑 만들어줘. 액션 버튼 포함` |
| 남에게 보낼 파일 | `/morning-brief 아침 브리핑 만들어줘. 출처 절은 빼줘` |
| 계정 없이 형식만 보기 | `/morning-brief 샘플 브리핑 보여줘` |

### Sections — 날씨는 기본, 환율은 요청

**아무 말도 하지 않으면 날씨 한 절이 붙습니다.** 아침에 가장 먼저 궁금한 것이라
매번 요청하게 두지 않았습니다.

| 이렇게 쓰면 | 붙는 절 |
|---|---|
| (아무 말 없음) | 날씨 |
| `Sections: 환율` | 환율만 — 기본 날씨는 따라붙지 않습니다 |
| `Sections: 날씨,환율` | 둘 다 |
| `Sections: none` | 하나도 안 붙음 |

`날씨` 와 `환율` 만 받습니다. 그 밖의 이름을 적으면 거부합니다. 날씨·환율 조회가
실패하면 그 절을 통째로 빼고 넘어갑니다 — 지어내지 않습니다.

### 액션 버튼은 정확한 한 문구로만

버튼은 **`액션 버튼 포함`** 이라는 문구가 요청에 그대로 있을 때만 붙습니다. "버튼도 달아줘"
같이 바꿔 말하면 붙지 않습니다. 이 판정은 자료를 읽기 전에 끝나므로, 나중에 "역시 버튼도"
라고 덧붙이면 처음부터 다시 요청해야 합니다.

버튼은 「일정과 무관한 미회신 메일」의 항목에만 붙습니다. 직접 결정해야 하는
일, 몸이 가야 하는 일, 돈·건강·자격증명이 걸린 일에는 붙지 않습니다. 메일 버튼이 약속하는
것은 **회신 초안까지**이며 발송은 하지 않습니다.

## 활용법 — 보기·인쇄·업데이트

### 미리보기 — 다 만들면 바로 뜹니다

브리핑을 만들 때마다(모양을 바꿔 다시 만들 때도) Claude 가 마지막에 파일을 공유합니다. Cowork 에서는 대화에
**파일 카드**가 붙고, 누르면 그 자리에서 미리 볼 수 있습니다.

### 브라우저로 열기 — itda-hyve 0.10.1 이상

카드가 뜨지 않는 환경이면 Claude 가 **"시스템 브라우저로 열까요?"** 라고 묻습니다. "응" 이라고 하면 itda-hyve 가
내 PC 의 기본 브라우저로 그 파일을 엽니다. 카드 안에서 인쇄가 잘 안 될 때도 "브라우저로 열어줘" 라고 하면 됩니다.

- itda-hyve **0.10.1 이상**에서, itda-hyve 화면의 **「파일·링크 열기」** 가 켜져 있을 때만 엽니다.
- Claude 가 내 PC 에서 파일을 여는 것이 싫으면 그 설정을 **꺼 두면 됩니다.** 그때는 파일 위치만 알려 주니,
  Finder(Windows 는 탐색기)에서 그 파일을 두 번 누르면 브라우저로 열립니다.
- 브리핑 파일은 연결한 폴더 안에 남습니다. 예약해 둔 무인 회차는 묻지 않고 파일 위치만 남깁니다.

### 모양 바꿔 다시 보기

이미 만든 브리핑을 다른 모양으로 보고 싶으면 이어서 말하면 됩니다. **메일을 다시 읽지 않고** 모양만 바꿔 다시 띄웁니다.

| 이렇게 말하면 | 모양 |
|---|---|
| "타임라인으로 다시" | 세로 시간축(기본) |
| "보고서 형식으로 다시" | 정독용 메모 |
| "표로 다시 보여줘" | 수와 표 |
| "인쇄용으로 다시" | A4 한 장 두 단 |

### 인쇄·PDF 로 저장

1. "인쇄용으로" 만들어 달라고 합니다. 다른 모양도 인쇄는 되지만 인쇄용이 A4 한 장에 맞춰져 있습니다.
2. 브라우저로 엽니다 — 위 「브라우저로 열기」, 또는 파일을 두 번 눌러서.
3. **⌘P**(Windows **Ctrl+P**) → 대상에서 **PDF 로 저장** 을 고르면 PDF 가 됩니다.

인쇄는 다크 모드여도 늘 밝은 색이고, 액션 버튼은 종이에 찍히지 않습니다. 남에게 보낼 파일이면
"출처 절은 빼줘" 를 함께 말하세요 — 페이지 끝의 메일 주소·본문 발췌가 빠집니다.

### itda-hyve 업데이트

판이 모자라면 Claude 가 브리핑을 만들지 않고 업데이트 순서를 안내합니다. 옛 판으로 만들면 받은 메일이 빈
브리핑이 나오기 때문에, 반쯤 빈 페이지를 내놓는 대신 먼저 멈춥니다.

1. 새 itda-hyve 설치본을 받아 지금 설치본을 바꿉니다. 설치본은 [itda.work/hyve](https://itda.work/hyve/) 에서 받습니다.
2. Claude Desktop 을 완전히 끝냈다가 다시 엽니다 — itda-hyve 가 새 판으로 다시 뜹니다.
3. 브리핑을 다시 요청합니다.

### 자주 겪는 문제

| 겪는 일 | 이렇게 하세요 |
|---|---|
| 파일 카드가 안 뜸 | "브리핑 파일 보여줘" 라고 하면 다시 공유합니다. 그래도 안 되면 "브라우저로 열어줘" |
| 브라우저로 열어 달라고 했는데 경로만 알려 줌 | itda-hyve 가 0.10.1 보다 옛 판이거나, itda-hyve 화면에서 「파일·링크 열기」 를 꺼 두었습니다. 알려 준 파일을 두 번 누르거나, 업데이트·설정을 확인하세요 |
| 업데이트 안내만 나오고 브리핑이 없음 | 의도한 동작입니다. 위 「itda-hyve 업데이트」 뒤 다시 요청하세요 |
| 인쇄하니 두 장이 됨 | "인쇄용으로" 만든 파일인지 확인하세요. 일정·메일이 아주 많으면 인쇄용도 넘칠 수 있습니다 |
| 다크 모드라 어둡게 보임 | 컴퓨터(OS)의 화면 설정을 따릅니다. 인쇄는 늘 밝은 색입니다 |

그 밖은 아래 「안 될 때」 를 보세요.

## 결과 페이지 읽는 법

파일은 연결한 폴더의 `outputs/` 아래에 `brief-2026-09-03.html` 같은 이름으로 저장됩니다.
열면 이런 자리들이 있습니다. 모양마다 놓이는 위치만 다릅니다 — 타임라인·인쇄용은 날씨가 머리 옆, 보고서는 머리 목록 안입니다.

| 자리 | 무엇이 있나 |
|---|---|
| 날짜 | `9월 3일 목요일` |
| 오늘 일정 | 오늘 일정 **전부**, 시간순(종일 일정이 맨 위). 시간·제목·장소·참석 인원. 취소된 일정은 줄을 긋고 "취소". 타임라인에서는 일정 사이가 1시간 이상 비면 "빈 시간 N시간" 줄이 들어갑니다 |
| 일정별 관련 메일 | 그 일정 곁(옆·아래·하위 행)에 — 제목·보낸 사람·날짜·회신 여부(미회신 · 답장 뒤 새 메일 · 회신함 · 모름). 어느 일정에도 이어지는 메일이 없으면 "오늘 일정과 이어지는 메일이 없어요" 한 줄 |
| 일정과 무관한 미회신 메일 | 사람이 보낸 메일 중 아직 답하지 않았고 오늘 일정과 이어지지 않는 것 — 제목·보낸 사람·날짜와 **내용 요약** |
| 대량 발송 메일 | 뉴스레터·자동 알림·결제·청구·광고처럼 답장을 기다리지 않는 메일. 종류 → 보낸 곳 → 최신 제목 3개("외 N통")로 **제목만** 모읍니다 |
| 날씨 절 | 기본으로 붙음(`Sections: none` 이면 빠짐) |
| 환율 절 | `Sections: 환율` 로 요청했을 때만 |
| 출처 (접혀 있음) | 무엇을 어느 계정에서 읽었는지, 원본 목록 |

- **어떤 메일이 어느 일정과 이어지나요?** 그 일정의 주최자·참석자와 주고받은 메일이 먼저이고, 그다음 일정 제목의
  낱말이 메일 제목에 있는 것입니다("회의·미팅·검토" 같은 흔한 말은 빼고 봅니다). 같은 대화의 메일은 가장 최근 한 통만
  보이고, 일정마다 다섯 통까지이며 넘으면 "N통 더" 라고 적습니다.
- **참석자 명단은 싣지 않습니다.** 참석 인원 수만 보여 줍니다.
- 일정이 없으면 "오늘은 잡힌 일정이 없어요", 답을 기다리는 메일이 없으면 "답을 기다리는 메일이 없어요" 한 줄이 나갑니다.
- 캘린더만 연결돼 있으면 일정까지, 메일만 연결돼 있으면 미회신 메일까지 나옵니다. 둘 다 없으면 두 문장짜리 페이지가 됩니다.
- 오류나 결손이 있으면 **그 사실을 말하는 한 줄**이 페이지에 들어갑니다. 빈 목록으로 위장하지 않습니다.

### 「출처」 절 — 무엇을 봤는지

페이지 끝에 접힌 「출처」를 펼치면 이렇게 확인할 수 있습니다.

- **수집 요약** — 역할별 상태(준비됨 · 미설정 · 확인 실패)와 **어느 계정에서 가져왔는지**
  (서비스 이름 · 계정 주소), 오늘 일정 건수, 관련 메일·미회신 메일 수, 경고 전부.
- **원본** — 메일은 보낸 사람·제목·날짜·판정·일정과 이은 근거·본문 발췌, 일정은 캘린더·제목·시간·주최자·상태.
  시각은 `9월 3일 오전 9:30 – 오전 10시` 처럼 사람이 읽는 표기로 나옵니다.
- 페이지의 줄마다 `출처 N` 링크가 붙고, 그 원본에는 **「이 항목의 근거」** 표시가 달립니다.

⚠️ 이 절에는 **메일 주소·제목·본문 조각이 그대로 들어 있습니다.** 파일을 남에게 보내야 하면
`/morning-brief 아침 브리핑 만들어줘. 출처 절은 빼줘` 라고 요청해 빼고 만드세요.

## 계정 없이 형식만 보기 — 샘플 브리핑

지어낸 시나리오로 **실제와 똑같은 형식**의 페이지를 그립니다. 수집만 건너뛸 뿐 정렬·문장·
렌더·검증은 실제 브리핑과 같은 길을 지나므로, 미리보기가 진짜 결과와 같은 모양이 됩니다.

### 언제 쓰나

- 강의·시연·회의에서 "이 스킬이 뭘 주는지" 를 한 장으로 보여줄 때
- 계정을 연결하기 전에 도입 여부를 판단할 때
- 남에게 보여줘야 해서 실제 메일·일정을 화면에 띄울 수 없을 때

### 이렇게 말하세요

```
/morning-brief 샘플 브리핑 보여줘
```

```
/morning-brief 샘플로 한 장 만들어줘
```

**`샘플 브리핑`** 또는 **`샘플로`** 라는 말이 요청에 있을 때만 이 길로 갑니다. 모양도 함께 고를 수 있습니다 —
`/morning-brief 샘플 브리핑 표로 보여줘`.

### 주제를 지정하려면 한 문장 덧붙이세요

청중에 맞춘 시나리오를 원하면 어떤 사람의 어떤 아침인지만 말하면 됩니다. Claude 가 그 주제로
시나리오를 **새로 씁니다**.

```
/morning-brief 샘플 브리핑 보여줘. 세무사 사무실 신고 시즌으로
```

```
/morning-brief 샘플 브리핑 보여줘. 온라인 쇼핑몰 운영 팀장의 화요일로
```

```
/morning-brief 샘플 브리핑 보여줘. 개발팀 배포일로
```

### 어떤 장면이 들어가나

시나리오에는 하루가 그려질 만큼의 장면이 들어갑니다. 기본 시나리오를 예로 들면 이렇습니다.

| 장면 | 기본 시나리오에 들어 있는 것 |
|---|---|
| 오늘 일정 | 4건 — 그중 **취소된 자리 하나** |
| 일정별 관련 메일 | 고객사 검토 자리에 **그 고객이 보낸 자료 메일**, 결산 통화에 **이미 답한 메일** |
| 일정과 무관한 미회신 | 3통 — 고객 문의 두 통, 내가 답한 뒤 새로 물어 온 한 통 |
| 날씨·환율 | 각각 한 줄씩 |

- **미회신은 2~3통일 때 가장 보기 좋습니다.** 너무 많으면 목록이 장면이 아니라 더미가 됩니다.
- 뉴스레터 같은 메일은 **목록에 오르지 않습니다.** 받은편지함의 사실감을 위해 시나리오에만 들어갑니다.
- 보고 싶은 장면을 직접 지정해도 됩니다. 예: `취소된 일정도 보여줘`, `회의마다 관련 메일을 하나씩`, `미회신은 두 통만`.

### 지어낼 때 지키는 것

- **실존 인물·회사·주소를 쓰지 않습니다.** 메일 주소는 예약 도메인(`example.com` 계열)만
  씁니다. 실제 고객사 이름을 넣으면 그 파일이 유출본이 되기 때문입니다.
- 일정 시각은 **실행하는 날에 얹힙니다.** 언제 열어도 "오늘"인 페이지가 됩니다.

### 아무 말 없이 요청하면 — 기본 시나리오

**세무사 사무실 아침**입니다. 실장 한 사람의 신고 시즌 하루로, 오늘 일정 4건과 메일 7통이 들어 있습니다.
고객사 검토 자리에 그 고객이 보낸 자료 메일이 이어져 있고, 일정과 무관한 고객 문의가 세 건 기다리며,
오후 교육 일정 하나가 취소돼 있습니다.

### 샘플이라는 표시는 지울 수 없습니다

- 페이지 **맨 위에 상시 띠**가 붙습니다 — "샘플 브리핑 — 실제 계정 데이터가 아니에요".
  접히지도, 스크롤로 사라지지도 않습니다.
- 제목이 "샘플 … 아침 브리핑" 으로 나가고, 「출처」 절의 계정란은
  **"샘플 · 에이전트 생성 시나리오"** 로 표시됩니다.
- 검증 단계가 이 둘을 **상호 배타**로 확인합니다. 샘플인데 띠가 없거나, 실제 브리핑인데 샘플
  표시가 섞이면 페이지가 통과하지 못합니다.
- **계정이 없다고 스킬이 스스로 샘플로 바꾸지 않습니다.** 계정이 없는 상태에서 그냥 브리핑을
  요청하면 두 문장짜리 페이지에 "샘플 브리핑을 요청하면 형식을 미리 볼 수 있어요" 한 줄만
  붙습니다. 전환은 언제나 당신이 말해야 일어납니다.

### 시나리오를 직접 주고 싶다면

같은 시나리오를 반복해 쓰거나(강의 교안 등) 문구를 손으로 다듬고 싶다면, 연결한 폴더에
JSON 파일 하나를 두고 이렇게 말하면 됩니다.

```
/morning-brief 샘플 브리핑 보여줘. sample-seed.json 이 시나리오로
```

파일에는 **등장인물**(이름·역할·메일 주소), **오늘 일정**(제목·시각·장소·주최자·참석자 주소·상태·캘린더),
**메일**(보낸 사람·제목·날짜·판정·본문), 선택으로 **날씨·환율 문구**와 **한두 문장 메모**가
들어갑니다. 형식이 맞는지는 Claude 가 확인하며, **틀리면 어느 항목이 왜 틀렸는지 알려 줍니다.**
기본 시나리오로 조용히 대체하지 않으므로, 알려 준 곳을 고쳐 다시 요청하면 됩니다.

### 샘플에서 버튼과 절

- 버튼을 보려면 실제 브리핑과 똑같이 정확 문구를 함께 씁니다 —
  `/morning-brief 샘플 브리핑 보여줘. 액션 버튼 포함`. 샘플 버튼의 안내문은 "샘플 시나리오의"
  로 시작해, 버튼을 누른 새 세션이 있지도 않은 메일을 찾아 나서지 않게 합니다.
- 날씨·환율의 **문구는 시나리오 안에 있습니다.** 어느 절을 보여줄지는 실제 브리핑과
  똑같이 `Sections:` 로 고릅니다(기본 날씨). 문구를 바꾸고 싶으면 "날씨는 비 오는 날로"
  처럼 시나리오 쪽을 말하세요. 시나리오에 그 절의 문구가 없으면 **다른 데서 끌어오지
  않고** 그 절을 비운 채 넘어갑니다.

## 예약해서 매일 아침 받기

예약 작업을 스킬이 대신 만들어 주지는 않습니다. 아래 문장을 **그대로 예약 작업 프롬프트로**
등록하면 됩니다.

```
morning-brief 스킬로 오늘 아침 브리핑을 만들어 주세요.
언어: 한국어
스타일: 타임라인        # 보고서 형식 · 표 · 인쇄용 중 하나로 바꿀 수 있습니다
Sections: 날씨          # 기본값이라 생략해도 됩니다. 빼려면 none
액션 버튼: 없음
무인 회차입니다 — 질문하지 말고 렌더까지 마친 뒤 파일 경로만 알려 주세요.
```

- 언어는 예약할 때의 언어를 적어 둡니다. 무인 회차가 추측하지 않게 하기 위해서입니다.
- 버튼을 원하면 마지막 줄 위에 `액션 버튼 포함` 을 한 줄로 넣습니다.
- **무인이라는 사실은 프롬프트에 적는 것이 유일한 방법입니다.** 그렇게 적어 두면 되묻지 않고,
  계정이 없는 역할은 비운 채로 페이지를 만듭니다. 미리보기도 띄우지 않고 파일 위치만 남깁니다.
- 예약 회차에서도 내 PC 의 itda-hyve 가 켜져 있어야 합니다.

## 안 될 때

| 증상 | 원인 / 해결 |
|---|---|
| itda-hyve 를 설치·연결하라는 안내가 나오고 멈춤 | itda-hyve 가 없거나 Claude Desktop 에 연결되지 않았습니다. 위 「사전 준비」 1 을 따르세요 |
| itda-hyve 를 업데이트하라는 안내가 나오고 멈춤(브리핑 없음) | itda-hyve 가 0.9.6 보다 옛 판입니다. 위 「itda-hyve 업데이트」 를 따르세요 |
| 폴더를 연결해 달라고 하고 멈춤 | Cowork 에 작업 폴더가 연결되어 있지 않습니다. 폴더를 연결한 뒤 다시 요청하세요 |
| 첫 수집에서 "파일을 찾지 못했다" 류의 오류 | 작업 폴더 밖에서 돌렸을 때 납니다. **연결한 폴더 안에서** 다시 요청하세요 |
| "캘린더·메일 계정 확인이 실패해 이 영역은 비어 있어요" 한 줄 | itda-hyve 가 그 계정에 로그인하지 못했습니다. itda-hyve 화면에서 계정 상태를 확인하거나 `itda-work:calendar`·`itda-work:email` 로 연결을 먼저 확인하세요 |
| "보낸편지함을 찾지 못해 메일 회신 여부를 가리지 못했어요" | 회신 판정이 전부 실패해 목록이 비었다는 뜻입니다. 후보가 없는 것과 다릅니다 — 메일 계정의 보낸편지함 설정을 확인하세요 |
| "받은편지함 메일이 많아 최근 것만 봤어요" | 최근 이틀 메일이 200통을 넘었습니다. 오래된 쪽이 빠졌을 수 있습니다 |
| "캘린더 일부를 읽지 못해…" · "반복 일정 일부의 회차를 계산하지 못해…" | 일부 캘린더가 실패했거나, 반복 규칙이 복잡해 회차를 계산하지 못했습니다. 나머지 일정은 그대로 실립니다 |
| 답해야 할 메일이 「대량 발송 메일」 에 들어감 | 보낸 쪽이 메일링 리스트·자동 발송 표지를 달았거나, 제목이 「(광고)」로 시작하거나, 주소가 `noreply`·`billing@` 같은 자동 발송 모양입니다. **최근 30일 안에 내가 메일을 보낸 적이 있는 주소**면 사람 메일로 봅니다 — 한 번 답장하면 다음부터는 미회신에 남습니다 |
| 결제·로그인 알림이 미회신에 남음 | 보낸 사람 주소가 사람 이름 같고(`kim@…`) 표지도 없는 자동 메일입니다. 모양만으로는 가릴 수 없어 남깁니다 |
| 관련 있어 보이는 메일이 미회신 목록에 있음 | 그 메일의 보낸 사람이 일정의 참석자가 아니고, 제목도 일정 제목과 겹치는 낱말이 모자란 경우입니다. 일정에 그 사람을 참석자로 넣어 두면 이어집니다 |
| Sections 이름을 거부함 | `날씨`·`환율` 두 가지만 받습니다(제외는 `none`) |
| 날씨 절이 안 나옴 | 조회가 실패하면 그 절을 통째로 뺍니다. 위치를 찾지 못해도 틀린 도시 대신 절을 뺍니다 — "부산 날씨로" 처럼 지역을 말하면 위치 조회 없이 나옵니다. `Sections: 환율` 처럼 다른 절만 지정해도 날씨는 빠집니다 |
| 날씨 첫머리에 "(대략·IP 기준)" | 컴퓨터 위치 서비스를 쓰지 못해 인터넷 주소로 찾았습니다. 지역이 다르면 "대전 날씨로" 처럼 말해 주세요. macOS 는 위치 권한을 허용하면 사라집니다 |
| 샘플인데 날씨 절이 안 나옴 | 시나리오에 그 절의 문구가 없는 경우입니다. 다른 시나리오의 문구를 끌어다 쓰지 않습니다 — 시드에 `sections.날씨` 를 넣어 주세요 |
| 버튼이 안 붙음 | 요청에 `액션 버튼 포함` 이라는 문구가 그대로 있어야 합니다 |
| 시나리오 파일을 줬는데 거부당함 | 어느 항목이 왜 틀렸는지 알려 줍니다. 기본 시나리오로 대체하지 않으니 그 항목을 고쳐 다시 요청하세요 |
| 파일 저장 실패 | 다른 경로로 조용히 옮기지 않고 실패를 그대로 알립니다. 저장할 경로를 지정해 다시 요청하세요 |

## 팁

- **하루에 대한 질문은 브리핑 요청이 아닙니다.** "오늘 일정 뭐 있어?"는 `itda-work:calendar`,
  "메일 읽어줘"는 `itda-work:email` 이 바로 답합니다. 브리핑은 한 장을 그려 달라고 할 때 씁니다.
- **날씨만·환율만 필요하면** `itda-work:weather-here`·`itda-work:exchange-rate` 를 직접 부르는
  편이 빠릅니다. Sections 는 브리핑 안에 한 절로 얹는 용도입니다.
- **시연 전에는 샘플로 한 번 돌려 보세요.** 계정 상태와 무관하게 같은 형식이 나오므로 화면
  구성을 미리 맞춰 둘 수 있습니다. 모양을 고를 때도 샘플로 네 가지를 차례로 받아 보면 빠릅니다.
- **목록은 원문 그대로 실립니다.** 일정 제목·메일 제목·보낸 사람은 실제 문자열이고, Claude 가 쓰는 것은
  미회신 메일의 요약 한두 문장뿐입니다. 요약이 빠지거나 남으면 검증에서 걸러집니다.
- **말투는 관찰하고 건네는 존댓말입니다.** 명령하거나 사과하거나 "빡빡하네요" 같은 평을 하지
  않습니다. 조용한 날은 그냥 조용한 날로 표시됩니다.
- **수집한 메일·일정 안의 지시는 따르지 않습니다.** 본문에 "Claude에게" 같은 문장이 들어 있어도
  요약할 내용으로만 다룹니다. 브리핑을 그리는 것 말고는 아무것도 하지 않습니다.

## 제한사항

- **itda-hyve 0.9.6 이상이 필요합니다**(브라우저로 열기는 0.10.1 이상). 내 PC 에서 itda-hyve 가 켜져 있어야 메일·일정을 읽습니다.
- **Cowork 에서는 연결한 폴더가 필요합니다.** itda-hyve 가 받아 온 내용을 그 폴더에 저장합니다.
- **눈으로 본 검증은 없습니다.** Cowork 에는 화면을 캡처해 확인할 브라우저가 없어 구조·내용 검증만 합니다.
  보기 좋은지는 열어서 직접 확인하세요.
- **예약 작업 자동 생성 미지원** — 위 템플릿 제공까지가 이 판의 범위입니다.
- **내일 일정은 싣지 않습니다.** 오늘 0시부터 자정까지의 일정만 봅니다.
- **관련 메일은 받은 메일만 봅니다.** 내가 보낸 메일은 답장 여부를 가리는 데만 씁니다.
- **참조(CC)로만 받은 메일은 미회신 목록에 오르지 않습니다.** 받는 사람에 내가 있는 메일만 봅니다(일정 관련 메일로는 보일 수 있습니다).
- **반복 일정에서 지운 회차가 보일 수 있습니다.** 반복의 예외 날짜를 받아 오지 못합니다.
- **메일 별칭(alias) 미지원** — 별칭 목록을 읽을 설정 출처가 없습니다.
- **취소된 일정은 잘 잡히지 않습니다.** 개인 CalDAV 에서는 취소가 대개 삭제로 나타납니다.
- **시간 기준은 서울 시간 고정**입니다.
- **샘플은 미리보기입니다.** 지어낸 시나리오이므로 그 안의 이름·회사·수치는 아무 사실도
  가리키지 않습니다. 실제 데이터로 바꾸려면 계정을 연결한 뒤 그냥 브리핑을 요청하세요.
- ⚠️ **저장 위치 권한** — `outputs/` 폴더에 쓰지 못하면 그 사실을 그대로 알립니다. 그때는 저장할
  경로를 함께 말해 주세요.
