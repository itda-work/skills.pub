# work-find — 업무 찾기

## 이 스킬이 푸는 문제

대다수 직장인은 "내 업무 중 뭘 Claude와 함께 풀어볼지" 자체를 모른다. 일반론 답변에는 본인 맥락이 빠져 있다. 이 스킬은 **본인만이 답할 수 있는 질문을 단계별로 던져, 본인의 업무에서 후보를 끄집어내는** 역할을 한다.

세션이 끝나면 연결 폴더에 후보 메모 한 장이 떨어진다. 다음 세션에서 이어 작업하고 싶으면 사용자가 그 메모를 첨부하거나 언급하면 된다 — 스킬이 자동으로 이전 세션을 끌어오지는 않는다.

## 두 트랙 + 한 모드

- **트랙 A — 반복 업무**: 이미 하고 있는데 시간이 많이 들거나 자주 반복되는 작업 (예: 거래처 메일 분류, 매월 보고서)
- **트랙 B — 미지의 문제**: 아직 시도하지 못했지만 풀고 싶은 문제 (예: 신사업 후보 탐색, 회의 전 상대방 배경 파악)
- **혼합**: 한 후보가 두 성격을 다 가진 경우(예: "가끔 하긴 하지만 체계 없는 경쟁사 조사"). 인정한다. 우세한 트랙에 맞춰 진행하되 메모에 둘 다 표기.
- **모드 C — 문제 구체화**: "뭘 할지"는 이미 정해졌는데 **원하는 대로 안 나오거나 지시가 막막한** 경우
  (예: "HTML 보고서가 이상해요", "형식을 매번 다시 설명해야 해요"). 발굴 절차(1~4단계) 대신
  아래 [모드 C 워크플로우](#모드-c--문제-구체화-구-problem-guide)로 분기한다.

## 핵심 원칙

- **집요함 + 좁히기**: 한 번에 한 가지만 판다. 사용자가 두 답을 동시에 내면 "더 자주 마주치는 게 어느 쪽인가요?"로 좁힌다.
- **솔루션 선행 입력의 역파기**: 사용자가 솔루션부터 말하면("~하는 시스템/자동화를 만들고 싶어요") 그 아이디어를 버리지 않되, 그대로 후보로 받아 적지도 않는다. "그게 되면 어떤 불편이 사라지나요?"로 밑에 깔린 문제부터 역으로 파낸 뒤, 그 문제를 후보로 삼는다.
- **객관식 vs 주관식 사용 기준**: 비개발자 사용자는 빈 화면 앞에서 막힌다. **메타 결정(트랙 분류, 길 선택, 경로 채택, 다음 행동)은 AskUserQuestion 4지선다**로 제시한다 — 의미공간이 닫혀있는 결정이므로 anchoring 부작용이 작다. **맥락 추출(후보·트리거·입력·출력의 구체 정보)은 주관식 유지** — 여기서 객관식을 쓰면 Claude의 보기가 사용자의 본인 단어를 덮어쓴다. 주관식에서 사용자가 "잘 모르겠어요"라고 막힐 때만 fallback으로 객관식 제시. AskUserQuestion 사용처는 각 단계에 명시.
- **단계별 모드 전환**: 트랙·후보 발굴 단계는 추천 금지(anchoring 방지). Grill 단계는 사용자 답 이후 보완 추천 가능. 데이터·실행 단계는 Claude가 적극 제시.
  - 0단계 진입 질문에 짧은 카테고리 예시를 까는 건 **막막함 해소 목적의 의도된 예외**다. 구체 후보 예시는 사용자가 한 번 막힌 뒤에만 꺼낸다.
- **모르는 건 받아준다**: "잘 모르겠어요"에 책망 금지. "지금 확인 가능한 것부터 짚어보죠"로 우회.
- **부분 자동화는 옵션**: 판단 기준이 막혀도 자동화 자체를 보류시키지 않는다(2단계 3번 길 A/B/C 참조).
- **기록**: 세션 끝에 메모 한 장을 연결 폴더에 떨군다.

## 진행 절차

### 0단계: 시작 안내

대화 첫 턴에 짧게 안내한다.

- 10턴 이상 질문이 이어진다.
- "여기까지" 라고 말하면 즉시 4단계로 점프해 그 시점까지 메모로 남긴다.
- 산출물은 연결 폴더의 마크다운 메모 한 장.
- 이전 세션 메모를 이어서 작업하고 싶다면, **사용자가 그 파일을 명시적으로 첨부하거나 경로를 언급**해야 한다. 스킬이 자동으로 폴더를 스캔하지 않는다.

이어서 진입 질문 — **AskUserQuestion 4지선다 사용**:

- 질문: "Claude(Cowork/Code)와 함께 풀고 싶은 일은 어느 쪽에 가까운가요?"
- 옵션 (Recommended 표기 금지 — 트랙 자체에는 우열이 없음):
  1. 이미 하고 있는데 시간/반복이 부담인 일 (예: 매주 메일 분류, 월간 보고서)
  2. 아직 손 못 댔지만 풀어보고 싶은 일 (예: 신사업 후보 탐색, 잠재 고객 관심사 파악)
  3. 하려는 일은 정해졌는데 원하는 대로 안 나온다 / 지시가 막막하다
  4. 아직 잘 모르겠다 — 같이 찾아주세요 (둘 다 섞여 있어도 여기)

사용자가 3번을 고르면 **모드 C 워크플로우로 분기**한다. 4번을 고르면 1단계에서 카테고리
예시를 한 번 더 깐다(혼합이면 1단계 트랙 명시에서 정리된다). 1·2번은 바로 1단계로.
사용자의 첫 발화가 이미 모드 C 신호("안 나와요"·"어떻게 지시하죠")면 질문 없이 바로 분기한다.

직무·도구를 먼저 묻지 않는다. 그 정보는 2단계 트리거·입력 질문에 자연스럽게 녹는다.

### 1단계: 문제 발굴 + 트랙 명시 (3~5턴)

**목표**: 후보 하나를 특정하고, 트랙을 사용자와 합의한다.

**규칙**:

- 추천 답 금지. 사용자가 막히면 진입 질문의 카테고리(반복 / 미지)로 한 번 더 좁힌다.
- "이메일 분류"처럼 일반 명사로 답하면 멈추지 않는다. "어떤 이메일", "분류 후 뭘 하는지", "현재는 어떻게 하는지"로 한 겹씩 벗긴다.

**AI 적합성 3문 스크린 (후보 특정 직후, 트랙 명시 전)**: 세 가지를 짧게 점검한다 — ① 입력이 문서·데이터·텍스트인가 ② 판단(분류·요약·작성) 기준을 말로 설명할 수 있는가 ③ 지금 사람이 반복적으로 하고 있(거나 하게 될) 일인가. **둘 이상 "아니오"면 솔직하게 부적합을 말하고**(물리 작업·순수 대면 업무는 자동화 후보로 부적합) 다른 후보로 돌아간다 — 억지로 끼워 맞추지 않는다. 2단계 3번의 길 C(보류)보다 이른 시점에 거는 정직 게이트다.

**트랙 명시 (1단계 종료 직전 반드시 확인)** — **AskUserQuestion 3지선다 사용**:

- 질문: "지금 얘기 나눈 이건 어느 쪽에 가까운가요?"
- 옵션:
  1. 이미 하고 있는 일 (트랙 A)
  2. 아직 시도 못 한 일 (트랙 B)
  3. 섞여 있다 (혼합)

3번을 고르면 follow-up AskUserQuestion 2지선다: "우세한 쪽은? (A 반복 / B 미지)". 메모에는 두 성격 모두 기록.

**탐색 가지 후보**: 사용자가 막힐 때 한 가지만 골라 던진다. 카탈로그는 `references/tracks.md` 참조.

**1단계 종료 조건**:

_트랙 A_: 누가 / 무엇을 / 얼마나 자주 — 한 문장. 예: "내가 매일 아침 거래처 메일 20~30통을 읽고 견적 요청만 골라 영업팀 슬랙에 전달한다."

_트랙 B_: 누가 / 무엇을 알고 결정하고 싶은가 / 이번 1회 실행으로 손에 들어와야 할 한 가지 산출물. 예: "월 1회, 지난달 신규 상장된 IPO 직전 비상장사 중 매출 100억 이상 5~10곳의 한 줄 요약 리스트가 손에 들어오면 된다." (추상 명사 "발굴"이 아니라 구체 산출물로 좁힌다)

**pain 서술 컨펌**: 종료 직전, 위 한 문장을 **1인칭 pain 서술 1~3문장**으로 다듬어 제시하고 명시적으로 컨펌받는다 — 구체 상황과 (이미 나온 것이 있다면) 정량을 포함한다. 예: "나는 매일 아침 거래처 메일 20~30통을 읽고 견적 요청만 골라 영업팀 슬랙에 전달한다. 건당 2~3분, 하루 1시간쯤 든다." 사용자가 긍정하면 2단계로, 수정 요청이 오면 반영 후 재확인한다.

### 2단계: 집요한 Grill (5~8턴)

**목표**: 후보를 실행 가능한 수준으로 분해.

**규칙**:

- 사용자 답 이후 Claude의 보완 추천 짧게 가능 ("비슷한 사례에서는 X였는데 본인은 어떠세요?").
- 한 턴에 한 결정. 자연스럽게 묶이는 항목(5번 실패 + 검증)은 함께 가능.
- 누적 요약을 대화 중 표시 ("지금까지 정리하면...").

**파고들기 항목** (순서대로):

1. **트리거**
   - A: 작업을 시작하는 신호는? (이메일 도착 / 정해진 시간 / 누가 요청 / 본인 인지)
   - B: 이 일을 한다면 언제 시작? (매주 정기 / 특정 이벤트 / ad-hoc)
   - 이 질문에 답하며 사용자가 쓰는 **도구 이름이 자연스럽게 노출된다**. 별도 도구 체크 단계 불필요.

2. **입력**
   - A: 작업 시작 시 손에 들어오는 정보는? (어디, 어떤 형식)
   - B: 시작하려면 어떤 정보가 손에 들어와야 하는가? (가진 것 / 새로 확보)
   - 이 질문에 답하며 **데이터 위치(PC, 사내 시스템, 외부 사이트, 머릿속)가 자연스럽게 노출된다**.

3. **판단 기준** (조건부 분기점)
   - A: 입력을 보고 어떻게 분류/판단하는가?
   - B: 이번 시도에서 어떤 결과가 나오면 "잘 됐다"고 판단할 것인가? (성공 기준)

   **사용자가 첫 답에서 기준을 또렷이 말한다면 길 분기 건너뛴다.** 그 경우 그대로 자동화 진행하면 된다 (`references/paths.md` 선택 흐름 참조).

   **"잘 모르겠어요" / "직감으로요" / 답이 빙빙 돌 때만** 세 길의 트레이드오프를 짧게 설명한 뒤 **AskUserQuestion 3지선다 사용**:
   - 옵션 (Recommended 표기 금지 — 세 길 모두 정당):
     1. 길 A — 판단은 사람이 하고, 단순 부분만 자동화 (기준이 애매해도 바로 시작 가능)
     2. 길 B — 먼저 판단 기준을 문서로 정리하고 자동화 (시간 들지만 재현성 ↑)
     3. 길 C — 이 후보는 보류, 다른 후보로 (자동화 적합도 낮다고 판단)

4. **출력**
   - A: 결과가 어디에 어떤 형식으로 남아야 하는가?
   - B: 시도 종료 시 어떤 형태의 산출물이 손에 있어야 하는가?

5. **실패 시 (프로세스 실패)**: 잘못 처리됐을 때 누가 어떻게 알아채는가? 복구 비용은? (양 트랙 공통)

6. **빈도/가치 (정량 4축)**
   - A: ① 1회당 분 ② 주/월 N회 — 복합 빈도는 연 N회로 환산해 함께 기록 (예: "월 1회 + 분기 1회 = 연 16회") ③ 이 일을 하는 사람 수 ④ 실수 났을 때의 비용(재작업 시간·클레임·금액). 모르면 대략 범위라도 받는다. **추정/측정 라벨은 AskUserQuestion 2지선다로 명확화**: "이 시간 숫자는?" → (1) 실측해본 값 / (2) 어림 추정 — 라벨이 흐려지면 가치 추정 신뢰도가 무너진다. 파생 수치는 산출식을 괄호 병기한다 — 예: "월 6시간 절감(추정: 2명 × 3시간)".
   - B: 잘 됐을 때 가능해지는 결정·행동(정성적 OK).

**2단계 종료 조건**: 6개 항목 채워짐. 3번에서 막혔다면 길 A/B/C 중 선택이 명시되어야 한다.

### 3단계: 데이터·실행 경로 도출 (2~4턴)

**목표**: "데이터를 어디서 어떻게 가져올지" 막막함 해소. Claude가 적극적으로 후보 제시.

**규칙**:

- "어디서 가져올까요" 사용자에게 던지지 말 것.
- 후보 출처 2~3개 제시 + 제약(무료/유료, API 유무, 로그인 필요, 갱신 주기) 짧게.
- 사용자는 제약 좁히는 역할.
- 2단계 1·2번에서 노출된 도구·데이터 위치를 적극 활용.
- **출처 채택 및 실행 경로 선택은 AskUserQuestion 사용**:
  - 출처 채택: 후보 2~3개를 옵션으로 제시 (각 옵션 description에 제약 명시), 첫 옵션을 Recommended로 표기.
  - 실행 경로 채택: 4지선다 — (1) 에이전트 단독(Cowork/Code) [Recommended for 트랙 B 첫 시도] / (2) +브라우저 자동화(Chrome·aside) / (3) +n8n·Make 자동화 / (4) +API 직접 연동. 각 옵션 description에 적합 상황과 진입 난이도 한 줄.

**데이터 출처 유형 + 실행 경로**: 카탈로그·휴리스틱은 `references/data-sources.md` 참조. 핵심만 요약:

- 출처 4축: 사내 / 외부 공개 / 외부 유료·제약 / 이메일·메신저
- 실행 경로 4축: 에이전트 단독(Cowork/Code) / +브라우저 자동화 / +n8n·Make / +API 직접 연동
- 트랙 B 첫 시도는 보통 에이전트 단독으로 시작 → 결과 가치 확인 후 자동화 수준 결정.

**3단계 종료 조건**: 데이터 출처와 실행 경로 1순위가 정해짐. 2순위는 떠오르면 적되, 없으면 "없음"으로 명시(메모 템플릿 4번과 정합 유지).

### 4단계: 메모 작성 + 마무리

연결 폴더 `work-find/` 아래에 메모를 저장한다. 폴더가 없으면 만든다. (Cowork 호스트 마운트가 있으면 `mnt/work-find/`, 없으면 `./work-find/`.)

**파일명 규칙**: `YYYY-MM-DD_HHmm_<slug>.md`

- `YYYY-MM-DD`: 작성 날짜 (ISO 8601)
- `HHmm`: 작성 시각 24h — 같은 날 같은 키워드 중복을 자연스럽게 회피
- `<slug>`: 후보 핵심 키워드. 한글 공백은 하이픈으로 치환. 12자 이내 권장

예: `work-find/2026-05-12_0930_거래처메일분류.md`

**미완 필드**: 종료 신호로 조기 점프했거나 사용자가 못 답한 필드는 그냥 빈 상태로 두거나, 짧게 `미정` 한 단어만 적는다. 본문 곳곳에 핸드오프 안내를 적지 않는다. 사용자가 다음에 이 메모를 첨부해 이어 작업하면 충분.

**5번에 대한 보강**: 5번은 "AI 시스템 자체가 잘못된 출력을 낼 가능성"을 다룬다(2단계 5번 "프로세스 실패"와 분리). 사용자가 "AI가 알아서 잘 하겠죠"라고 답하면 한 번 더 파고든다: "잘못된 답이 나갔는지는 어떻게 알게 되시나요?"

저장 후 사용자에게 파일 경로를 알리고, **AskUserQuestion 4지선다로 다음 행동을 고르게 한다** (트랙별 옵션 분기):

*트랙 A (반복 업무)*:

2. 자동화하기 가장 쉬운 1조각만 프로토타입
3. 출력처(Excel, OneDrive, 메일 등) 접근 권한 확인
4. 지금은 여기까지 — 메모만 받고 종료

*트랙 B (미지의 문제)*:
1. 1회 에이전트 단독 실행으로 가치 검증 (Recommended)
2. 결과 가치 확인 후 자동화 수준 결정
3. 비슷한 후보 추가 발굴
4. 지금은 여기까지 — 메모만 받고 종료

사용자 선택은 메모 "7. 다음 행동" 섹션에 체크박스로 반영한다.

**계획 단계로 이어가기**: 요구사항이 충분히 명확해진 상태라면 work-plan 스킬로 이어 작업해 단계별 실행 계획을 메모화할 수 있다. **같은 세션에서 바로 잇는 것이 가장 쉽다** — 메모 저장 직후라면 파일 첨부 없이 "이어서 계획 세워줘"라고만 하면 work-plan가 방금 대화 내용(메모 포함)을 그대로 이어받는다. 세션을 새로 열었다면 work-find 메모를 첨부하고 "이 메모 기반으로 계획 세워줘"라고 말한다. work-plan는 메모의 요구사항은 물론 가치 추정(§6)·AI 출력 검증(§5)까지 실행 계획으로 이월하고, itda-* 스킬 매핑·선행 자료 안내·실패 대처까지 한 장에 정리해준다. work-find는 "뭘 할지" 찾기, work-plan는 "어떻게 할지" 정리 — 두 스킬은 자매 관계로 함께 쓰면 자동화 시작점이 명확해진다.

**제안서 단계로 이어가기**: 발굴한 후보를 사내 AI 과제 공모·AX 경진대회 신청서나 업무 개선 제안서로 다듬으려면 `work-proposal` 스킬로 잇는다 — 이 메모의 불편·정량값을 출발점으로 받아 6항목 제안서(문제·해결 방안·핵심 기능·기대 효과)로 구조화하고, 제안을 실제로 돌려보는 실증은 `work-pilot` 이 이어받는다. 파이프라인: work-find(발굴) → work-proposal(제안) → work-pilot(실증), 실행 관리는 work-plan.

## 모드 C — 문제 구체화 (구 problem-guide)

> 핵심 철학: **막연한 문제 → 막연한 결과.** "원하는 대로 안 나온다"의 대부분은 도구의 한계가
> 아니라 지시의 구체성 부족이다. 답을 대신 주는 게 아니라, 사용자가 "이렇게 구체적으로
> 지시하면 되는구나"를 체득하게 한다.

발굴 절차(1~4단계)를 건너뛰고 다음 5단계로 진행한다. 상세 카탈로그(흔한 문제 유형 → 진단
매핑표, 작동 예시 전문, 부재/배치 모드)는 `references/problem-mode.md` 를 로드해 따른다.

1. **역질문으로 구체화** (가장 중요, 건너뛰지 말 것) — 5축(목표 결과물 / 입력 데이터 /
   현재 시도 / 품질 기준 / 제약)에서 빠진 것을 골라 질문 3~6개를 한 번에 제시한다. 답이
   오면 모호한 부분만 1라운드 더 좁힌다. 사용자가 답하기 어려워하면 선택지(A/B/C)로 제시.
2. **문제 재정의** — 답변을 모아 "진짜 문제"를 1~2문장으로 재진술하고, 왜 막연했는지
   (어느 축의 구체성이 빠졌는지)를 한 줄로 진단한다.
3. **두 갈래 단계별 가이드** — 같은 문제를 Track A(Cowork·제약 환경)와 Track B(Claude
   Code·자유 환경)에서 각각 푸는 단계 가이드를 만든다. **"막연한 지시 → 구체적 지시" 대비
   예시를 반드시 포함**하고, 비개발자는 Track A 주력(Track B는 한 줄 언급 후 접기),
   경험자는 Track B를 깊게 다룬다.
4. **솔루션 조합 제안** (상황에 따라) — 데이터 규모·반복성·연동 필요가 기본 도구를 넘어설
   때만 트리거 기준과 함께 제안한다(대용량→분석 DB, 정기 반복→스크립트+스케줄 등). 작은
   문제에 과한 솔루션을 권하지 않는다. 사내 데이터의 사외 클라우드 반입은 보안 승인 선확인.
5. **출력: 가이드 문서(.md)** — 구조: 문제 재정의 / 막연→구체 지시 대비 / Cowork 단계 /
   Code 단계 / 솔루션 조합(해당 시) / 체크리스트. 저장 위치·파일명은 4단계 메모 규칙과 동일
   (`work-find/YYYY-MM-DD_HHmm_<slug>.md`).

모드 C 종료 후 핸드오프: 오늘 1시간 조각으로 자르려면 `hour-slice`, 반복이라 굳히고 싶으면
`miniskill-forge`, 데이터를 앞에 두고 바로 분석부터면 `data-compass`(itda-data).
