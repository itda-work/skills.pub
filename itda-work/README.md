# itda-work

> **🟢 처음이세요? → [GUIDE.md](GUIDE.md) 한 장만 보세요.** 코드 몰라도 됩니다. 채팅창에 평소 말로 고민을 적으면 코치가 안내해요.

**AI 활용 여정 코칭 스킬팩** — "막상 뭘 해볼지 막막하다"부터 "뭘 맡기고 뭘 지킬지 기준이 없다",
"오늘 1시간 안엔 뭘 만들지"까지, AI 활용 여정의 각 막막함을 단계별로 안내하는 도구 6개를 담았습니다
(탐색·구체화 단계의 `work-find`·제안서 `work-proposal`·파일럿 `work-pilot`·브리프 `task-brief` 도 2026-09 재정비(#1648)로 이 팩에 합류해 여정 ①~④가 한 팩에 있습니다).
AI 활용의 총량은 `사용자 능력 × 모델 성능`의 곱이라, 내 일을 구조로 그리는 앞자리가 0이면 모델이
좋아져도 결과는 0에 가깝습니다 — 이 팩은 그 앞자리를 만드는 여정을 코칭합니다.

## 스킬 (여정 순서)

| 여정 | 스킬 | 막막함의 종류 | 하는 일 |
|------|------|--------------|---------|
| ① 탐색·구체화 | `work-find` (업무 찾기) | "뭘 해볼지 모르겠다" / "원하는 대로 안 나온다" | 발굴 인터뷰(반복 업무·미지 문제 두 트랙) + 문제 구체화 모드(역질문→Cowork/Code 두 갈래 가이드)로 후보 메모를 만든다 |
| ② 구조화 | `work-redesign` (업무 구조화) | "뭘 AI한테 맡기고 뭘 내가 해야 하지?" | 업무를 태스크→행동 단위로 쪼개고 가치×AI개입 4분면으로 매핑해 업무 지도를 만든다 |
| ② 구조화 보조 | `time-audit` (시간 감사) | "내 시간이 어디로 가는지 모른다" | 캘린더 실적을 결정론 스크립트로 집계해 소요 시간·병목을 실측한다 |
| ② 구조화 보조 | `stakeholder-map` (이해관계자 지도) | "누구한테 뭘 먼저 넘겨야 하지" | 이해관계자별 역할·요청·선행 전달물(제약 조건)을 정리한다 |
| ③ 계획 | `work-plan` (실행 계획) | "그래서 어떻게 시작하지?" | 요청·메모를 적합한 itda-* 스킬 조합으로 매핑해 실행 계획 한 장을 만든다 |
| ④ 실행 조각 | `hour-slice` (1시간 조각 자르기) | 하고 싶은 건 큰데 1시간 안엔 뭘? | 구체화된 문제를 **오늘 ~1시간 안에 눈에 보이는 결과가 나오는 한 조각**으로 자른다 |
| ⑤ 굳히기 | `miniskill-forge` (미니스킬 만들기) | 이걸 매번 자동으로 굳히고 싶다 | 반복 작업을 재사용 미니스킬로 Cowork에서 도출한다 |
| ③ 계획 보조 | `task-brief` (작업 브리프) | "에이전트에 뭘 시킬지 정리가 안 된다" | 모호한 요청을 범위·검증 방법·완료 정의 3요소 브리프 한 장으로 다듬는다 (2026-09 itda-work 에서 합류) |
| ④ 제안·실증 | `work-proposal` (제안서) · `work-pilot` (파일럿) | "이걸 사내 과제로 올리려면?" | 발굴한 후보를 제안서 뼈대로 구조화하고 Cowork 안에서 돌아가는 파일럿으로 만든다 (2026-09 itda-work 에서 합류) |

## funnel

```
막연한 불편 ─▶ work-find(탐색·구체화) ─▶ work-redesign(구조화: 없앨 것·지킬 것·맡길 것)
                                        │      ├─ time-audit(시간 실측) · stakeholder-map(협업 지도)
                                        ▼      ▼
                                  work-plan(실행 계획) ─▶ hour-slice(오늘 1시간 조각)
                                                              └─▶ miniskill-forge(반복이면 미니스킬로 굳히기)
```

각 스킬은 독립 호출도 되지만, 위 순서로 이어 쓰면 "막막함 → 업무 지도 → 오늘 만들 한 조각"이 가장
매끄럽다. 데이터를 앞에 두고 바로 분석부터 하고 싶으면 `data-compass`(itda-data 팩)로,
발굴한 후보를 사내 과제 제안서·파일럿으로 다듬으려면 `work-proposal`·`work-pilot`(같은 팩)으로 잇는다.

## 설계 원칙

- **떠먹이되 숟가락 쥐는 법을 남긴다** — 대신 끝내주는 게 아니라, 다음엔 혼자 시작하도록 *시작하는 법*을 남긴다.
- **추천보다 선택지** — 메타 결정(트랙·길 선택)은 탭 가능한 보기로, 맥락 추출(후보·입력·기준)은 사용자 본인 언어로 받는다.
- **1시간 실현가능성** — 손에 있는 표면(Cowork 단독·첨부파일·설치된 스킬·커넥터)만으로 가시적 결과가 나오는 크기로 자른다.
- **Cowork 친화** — 비개발자·모바일 입문자를 1순위로 가정한다. 사내 데이터는 비식별·표본 우선, 산출물은 항상 초안.
